## 산술 연산자

| 연산자 | 하는 일 | `10`과 `3`으로 |
|---|---|---|
| `+` | 더하기 | `13` |
| `-` | 빼기 | `7` |
| `*` | 곱하기 | `30` |
| `/` | 나누기 | `3.3333...` |
| `%` | 나눈 **나머지** | `1` |
| `**` | 거듭제곱 | `1000` |

`/`와 `%`가 헷갈리면 초등학교 나눗셈을 떠올리면 됩니다. `10 ÷ 3 = 3 … 1`에서
**몫 쪽이 `/`, 나머지 쪽이 `%`** 입니다. 다만 자바스크립트의 `/`는 몫이 아니라
소수까지 다 계산합니다. 정수와 실수를 구분하지 않는 언어라서 그렇습니다.

`%`가 실제로 쓰이는 자리는 "나누어떨어지는가"를 볼 때입니다. `n % 2`가 `0`이면 짝수입니다.

`**`는 순서가 중요합니다. `2 ** 3`은 2를 세 번 곱한 `8`, `3 ** 2`는 3을 두 번 곱한 `9`입니다.

## 계산 순서

곱셈·나눗셈이 덧셈·뺄셈보다 먼저입니다. 수학과 같습니다.

```js
3 + 4 * 2      // 11   4 * 2 를 먼저 하고 3을 더합니다
(3 + 4) * 2    // 14   괄호가 있으면 그게 먼저입니다
```

외울 목록이 길어 보이지만, 실무에서는 **헷갈릴 것 같으면 괄호를 칩니다.**
괄호는 공짜고, 읽는 사람이 순서를 고민하지 않아도 됩니다.

## 비교 연산자

결과는 언제나 `true` 아니면 `false`입니다. 즉 **불리언**입니다.

```js
typeof (5 >= 5)    // 'boolean'
```

이게 중요한 이유는 다음 주에 드러납니다. 조건문이 받는 재료가 바로 이 값입니다.

| 연산자 | 뜻 |
|---|---|
| `>` `<` | 초과 · 미만 (같으면 `false`) |
| `>=` `<=` | 이상 · 이하 (같으면 `true`) |
| `===` | 같다 |
| `!==` | 다르다 |

`===`가 등호 세 개인 게 이상해 보일 겁니다. 등호 두 개짜리(`==`)도 있는데, 둘은 다르게
동작합니다. 지금은 **`===`만 쓰세요.** 차이는 형변환을 다루는 주차에서 정면으로 봅니다.

## 논리 연산자

| 연산자 | 뜻 | 언제 `true`인가 |
|---|---|---|
| `&&` | 그리고 | 양쪽 다 참일 때만 |
| `\|\|` | 또는 | 한쪽이라도 참이면 |
| `!` | 반대로 | 거짓일 때 |

`!`를 불리언이 아닌 값에 붙이면 재미있는 일이 생깁니다.

```js
!0      // true    ← 0을 "거짓 같은 값"으로 보고 뒤집었습니다
!''     // true    ← 빈 문자열도 마찬가지
!1      // false
!'가'   // false
```

불리언이 아닌 값도 참/거짓 중 한쪽으로 취급된다는 뜻입니다. 이걸 **truthy / falsy**라고
부릅니다. 어떤 값이 falsy인지는 몇 개 안 되니 그때그때 확인하면 되고, 이 성질이 실제로
문제가 되는 상황은 뒤에서 다룹니다.

## 복합 할당

```js
let 총액 = 10000;
총액 += 5000;      // 총액 = 총액 + 5000 과 같습니다
```

`-=`, `*=`, `/=`도 같은 방식입니다. 오른쪽 계산 결과를 다시 왼쪽 변수에 넣습니다.
`const`로 선언한 변수에는 쓸 수 없습니다. 재할당이니까요.

## 타입이 다른 값을 섞으면

```js
'5' + 2     // '52'   문자열이 됩니다
'5' - 2     // 3      숫자가 됩니다
```

같은 자리에 있는 두 값인데 결과 타입이 다릅니다. 이유는 **`+`만 두 가지 일을 하기 때문**입니다.

- `+`는 숫자 덧셈이기도 하고 **문자열 이어붙이기**이기도 합니다. 한쪽이 문자열이면
  자바스크립트는 "이어붙이라는 뜻이겠지" 하고 다른 쪽도 문자열로 바꿔버립니다.
- `-`는 이어붙이기라는 뜻이 없습니다. 뺄셈밖에 못 하니 양쪽을 숫자로 바꿉니다.

W2에서 본 **암묵적 변환**이 이겁니다. 내가 시키지 않았는데 언어가 알아서 타입을 바꾼 것이죠.
규칙이 여기서 끝나지 않고 꽤 깊게 이어지는데, 전체는 형변환을 다루는 주차 몫입니다.

지금 가져갈 결론은 하나입니다. **숫자로 계산할 값이면 숫자로 만들어놓고 계산하세요.**
`Number()`로 바꾸는 법은 W2에서 배웠습니다.

## 4단계 해설 — 윤년 식 만들기

여기부터는 **4단계의 답에 가깝습니다.** 30분은 붙들어보고 오세요.

### 규칙을 한 줄씩 옮기기

말로 된 규칙을 통째로 옮기려 하면 막힙니다. **한 줄씩 따로** 옮기고 나중에 합칩니다.

> 1. 4로 나누어떨어지면 윤년이다

"나누어떨어진다"는 **나머지가 0**이라는 뜻입니다.

```js
year % 4 === 0
```

> 2. 단, 100으로 나누어떨어지면 윤년이 아니다

윤년이 되려면 **100으로 나누어떨어지면 안 됩니다.** "~가 아니다"는 `!==`입니다.

```js
year % 100 !== 0
```

> 3. 단, 400으로 나누어떨어지면 윤년이다

```js
year % 400 === 0
```

여기까지가 절반입니다. 조각 셋이 나왔고, 각각은 `true` 아니면 `false`를 돌려줍니다.
**비교의 결과는 불리언**이라고 1단계에서 확인한 그 값입니다.

### 조각을 합치기

1번과 2번은 **둘 다** 만족해야 합니다. "4의 배수이면서 100의 배수가 아니다"니까요.
둘 다여야 하니 `&&`입니다.

```js
year % 4 === 0 && year % 100 !== 0
```

이걸로 2024년(윤년)과 1900년(평년)은 맞습니다. 그런데 2000년을 넣어보면 `false`가 나옵니다.
2000은 100으로 나누어떨어져서 2번에 걸려버리거든요. 실제로 2000년은 윤년입니다.

3번 규칙이 바로 그 구제 조항입니다. **위에서 탈락했더라도** 400의 배수면 윤년입니다.
"이것이거나 저것이거나"이므로 `||`입니다.

```js
const isLeapYear = (year % 4 === 0 && year % 100 !== 0) || year % 400 === 0;
```

### 여기서 한 번 더

위 코드는 동작은 하는데, 읽는 사람이 `% 4`, `% 100`, `% 400`을 눈으로 따라가며
"아 이게 1번 규칙이구나" 하고 되짚어야 합니다. 규칙을 이미 아는 사람만 읽을 수 있는 코드입니다.

조각마다 이름을 붙여보세요.

```js
const isDivisibleByFour = year % 4 === 0;
const isDivisibleByOneHundred = year % 100 === 0;
const isDivisibleByFourHundred = year % 400 === 0;

const isLeapYear = (isDivisibleByFour && !isDivisibleByOneHundred) || isDivisibleByFourHundred;
```

마지막 줄을 소리 내어 읽어보세요. "4의 배수이고 100의 배수가 아니거나, 400의 배수면 윤년."
윤년 규칙 문장이 그대로 나옵니다. 주석이 필요 없어집니다.

얻는 게 하나 더 있습니다. 이번 과제는 **규칙 세 개의 참·거짓을 각각 출력**해야 하는데,
이름이 붙어 있으면 그냥 갖다 쓰면 됩니다.

```js
console.log(`${year}년 → 4의 배수: ${isDivisibleByFour} / 100의 배수: ${isDivisibleByOneHundred} / 400의 배수: ${isDivisibleByFourHundred} / 윤년: ${isLeapYear}`);
```

이름을 안 붙였다면 `year % 4 === 0`을 판정식에 한 번, 출력에 또 한 번, 같은 걸 두 번 적게 됩니다.
그러다 4를 다른 숫자로 고칠 일이 생기면 두 군데를 다 고쳐야 하고, 한 군데를 빠뜨리면
**출력과 판정이 어긋난 채로 아무 에러 없이 돌아갑니다.** 찾기 아주 성가신 버그입니다.

W2에서 값에 이름을 붙였던 것과 같은 이야기입니다. 이번에는 그 값이 **계산 결과**일 뿐입니다.

### 왜 이 순서인가

`||`로 이어붙인 두 덩어리를 각각 읽어보면 이렇게 됩니다.

- 왼쪽 `(year % 4 === 0 && year % 100 !== 0)`: 평범한 윤년. 4의 배수이고 100의 배수가 아님
- 오른쪽 `year % 400 === 0`: 예외적으로 구제되는 윤년

둘 중 **하나라도** 참이면 윤년입니다. 그래서 `||`입니다.

여섯 해로 확인해보면 이렇게 갈립니다.

| 연도 | `%4===0` | `%100!==0` | 왼쪽 덩어리 | `%400===0` | 결과 |
|---|---|---|---|---|---|
| 2024 | `true` | `true` | `true` | `false` | **윤년** |
| 2023 | `false` | `true` | `false` | `false` | 평년 |
| 1900 | `true` | `false` | `false` | `false` | 평년 |
| 2000 | `true` | `false` | `false` | `true` | **윤년** |
| 2100 | `true` | `false` | `false` | `false` | 평년 |
| 2400 | `true` | `false` | `false` | `true` | **윤년** |

1900과 2000을 나란히 보세요. 왼쪽 덩어리는 둘 다 `false`로 똑같습니다.
**오른쪽에서 갈립니다.** 3번 규칙이 하는 일이 이 표에 그대로 보입니다.

### 괄호를 빼면

빼도 결과가 똑같습니다. 여섯 해 전부 그대로입니다.

```js
year % 4 === 0 && year % 100 !== 0 || year % 400 === 0
```

**`&&`가 `||`보다 먼저 계산되기 때문**입니다. 곱셈이 덧셈보다 먼저인 것과 같은 이치로,
논리 연산자에도 순서가 있습니다. 그래서 괄호를 안 써도 자바스크립트는 알아서
`(A && B) || C`로 묶어 읽습니다.

그럼 괄호는 쓸모없을까요. 결과만 보면 그렇습니다. 그래도 남겨두는 편이 낫습니다.

- **읽는 사람이 순서를 몰라도 됩니다.** 우선순위 표를 외운 사람만 읽을 수 있는 코드보다,
  누가 봐도 한 번에 읽히는 코드가 낫습니다
- **나중에 고칠 때 안전합니다.** 조건을 하나 더 붙이거나 순서를 바꿀 때, 괄호가 없으면
  의도와 다르게 묶여도 눈치채기 어렵습니다

괄호는 공짜입니다. 헷갈릴 것 같으면 치세요.

### 자주 나오는 실수

**`=`와 `===`를 헷갈림**

```js
year % 4 = 0      // 에러. 왼쪽은 변수가 아니라 계산 결과입니다
year % 4 === 0    // 비교
```

`=`는 "넣어라", `===`는 "같은가?"입니다. 아예 다른 일을 합니다.

**`!==`를 `!=`로 씀**

`!=`도 동작하긴 하는데, `===`와 `==` 사이에 있는 문제가 여기에도 똑같이 있습니다.
지금은 `===`와 `!==`만 쓰세요. 이유는 형변환 주차에서 봅니다.

**`if`로 풀려고 함**

```js
if (year % 4 === 0) { ... }    // 이번 주에는 금지
```

`year % 4 === 0`은 그 자체로 이미 `true`나 `false`입니다. 조건문은 그 값을 **받아서**
흐름을 가르는 도구인데, 지금은 값을 만드는 것까지만 합니다. 조건문은 다음 주에 씁니다.
