# W2 — 변수와 값

**주제**: `let`/`const`, 원시 타입, `typeof`, 타입 변환, 템플릿 리터럴

## 학습목표

W1의 `hello.js`에는 값이 그대로 적혀 있습니다. 같은 값을 두 번 쓰려면 두 번 타이핑해야 하고,
바꾸려면 전부 찾아 고쳐야 합니다. **값에 이름을 붙이는 것**이 이번 주 주제입니다.

실행은 이제 Node로만 합니다. 브라우저는 화면을 다뤄야 할 때 다시 씁니다.

- 값에 이름을 붙여 변수로 선언하고, 그 이름으로 값을 다시 꺼내 쓸 수 있다.
- `let`과 `const`의 차이를 재할당 가능 여부로 설명하고, 기본으로 무엇을 쓸지 정할 수 있다.
- 숫자 · 문자열 · 불리언 · `undefined` · `null`을 구분하고 `typeof`로 확인할 수 있다.
- 타입이 왜 필요한지, 같은 `+`가 값에 따라 다르게 동작하는 이유를 설명할 수 있다.
- `Number` · `String` · `Boolean`으로 값의 타입을 의도적으로 바꿀 수 있다.
- 내가 바꾸는 변환과 언어가 알아서 하는 변환의 차이를 말할 수 있다.
- `undefined`와 `null`이 각각 어떤 상황에서 생기는지 예를 들 수 있다.
- 템플릿 리터럴로 값과 문장을 섞어 한 줄로 조립할 수 있다.
- 변수 이름만 보고 무엇이 들어 있는지 짐작되도록 이름을 지을 수 있다.
- W1에서처럼 에러를 만나면 메시지를 읽고, 무엇을 하지 말라는 뜻인지 말할 수 있다.

## 과제: 값에 이름 붙이기

`week-02/values.js`를 만들어 `node week-02/values.js`로 실행합니다.
관찰한 것은 `week-02/notes.md`에 적습니다. 두 파일 모두 직접 만드세요.

아래 항목은 순서대로 하면 됩니다. **실험하고, 결과를 보고, 왜 그런지 적는 것**이 한 묶음입니다.

### 요구사항

- [ ] W1의 `hello.js`에서 값을 그대로 적었던 자리를 변수로 바꿔 시작하기
- [ ] 같은 `+`가 다르게 동작하는 것 확인하기
  - `3 + 4`와 `'3' + '4'`를 각각 출력해 비교
  - 결과가 왜 다른지 `notes.md`에 한 줄. `+`가 **무엇을 보고** 판단하는지가 답입니다
- [ ] 한 변수에 숫자를 넣어 `typeof`를 찍고, **같은 변수에** 문자열을 넣어 다시 찍기
  - 두 결과가 다릅니다. 그렇다면 타입은 변수의 것일까요, 값의 것일까요
  - 근거와 함께 `notes.md`에 한 줄
- [ ] 다섯 가지 값을 변수에 담고 `typeof`로 타입 출력하기
  - 숫자 · 문자열 · 불리언 · `undefined` · `null`
  - 다섯 개 중 결과가 예상과 다른 것이 하나 있습니다. 무엇인지 `notes.md`에 기록
  - 이유는 지금 찾지 말고 넘어가세요. 10주차 즈음 형변환을 다룰 때 나옵니다
- [ ] `undefined`와 `null`을 각각 만들어보기
  - 선언만 하고 값을 주지 않은 변수를 출력하면 무엇이 나오는지
  - `null`을 직접 넣은 변수와 비교
  - 둘 다 "값이 없다"는 뜻인데 왜 나뉘어 있을까요. **누가 그 값을 넣었는지**를 기준으로 `notes.md`에 정리
- [ ] `const`로 선언한 변수에 재할당을 시도해 **일부러 에러를 내기**
  - 에러 메시지 원문을 `notes.md`에 그대로 옮기기
  - 그 메시지가 무엇을 하지 말라고 하는지 한 줄로 해석
  - 확인한 뒤에는 그 줄을 주석 처리해 나머지 코드가 실행되게 할 것
- [ ] 같은 값을 `let`으로 선언해 재할당해보고, 두 경우의 차이를 확인하기
  - `const`가 막고 있는 것이 정확히 무엇인지 `notes.md`에 한 줄
- [ ] 값의 타입을 직접 바꿔보기
  - `'42' + 8`과 `Number('42') + 8`을 각각 출력해 비교
  - `String(42)`, `Boolean(1)`, `Boolean(0)`의 결과를 `typeof`와 함께 출력
  - `Number('안녕')`의 결과도 출력해 기록 (이유는 뒤에서 형변환을 다룰 때)
  - 둘째 줄에서 **내가 한 일**과 첫째 줄에서 **자바스크립트가 한 일**의 차이를 `notes.md`에 정리
- [ ] 템플릿 리터럴로 문장 조립하기
  - 예: `` `${customerName}님의 주문 ${orderCount}건` ``
  - 같은 문장을 `+`로도 만들어보고 어느 쪽이 읽기 쉬운지 `notes.md`에 한 줄
- [ ] `node` REPL에서 `typeof`를 직접 몇 번 쳐보기
  - W1에서 익힌 REPL을 값 확인용으로 쓰는 연습입니다. 파일을 만들 필요가 없습니다

### 제약

- `var` 사용 금지
  - 스코프 규칙이 달라서, 지금 익히면 나중에 지워야 합니다. 옛날 코드에서 만나면 그때 다룹니다
- 변수 이름에 `a`, `b`, `x`, `temp` 금지
  - 이름이 곧 설명입니다. 이름을 못 정하겠다면 그 값이 무엇인지 아직 정하지 못했다는 뜻입니다
- 문자열과 값을 섞을 때는 템플릿 리터럴을 쓸 것 (비교용으로 한 번만 `+` 허용)
- 값을 두 번 이상 쓰는 자리에 값을 그대로 적지 말 것
  - 그러려고 변수를 배웁니다
- 에러는 지우지 말고 기록할 것 (W1과 같은 규칙)
- 치트노트는 직접 돌려본 뒤에 펴볼 것
  - 먼저 읽으면 결과를 확인하는 작업이 되고, 기억에 남지 않습니다

### 완료 기준

`notes.md`만 읽고도 아래에 답할 수 있으면 통과입니다.

- `node week-02/values.js`가 에러 없이 끝까지 실행됨
- **`3 + 4`와 `'3' + '4'`의 결과가 다른 이유**가 적혀 있음
- **타입을 가지는 것이 변수인지 값인지**가 근거와 함께 적혀 있음
- 다섯 값의 `typeof` 결과가 출력되고, 예상과 달랐던 항목이 기록되어 있음
- **`undefined`와 `null`을 나누는 기준**이 적혀 있고, 각각의 예가 하나씩 있음
- `const` 재할당 에러 메시지가 원문 그대로 남아 있고, `const`가 막는 것이 무엇인지 적혀 있음
- **`'42' + 8`과 `Number('42') + 8`의 차이**와, 그 차이를 만든 것이 누구인지가 적혀 있음
- `let`과 `const` 중 무엇을 기본으로 쓸지와 그 이유가 적혀 있음
  - 이 답은 형변환을 다루는 주차에서 다시 꺼내 봅니다. 지금 생각을 그대로 남겨두세요
