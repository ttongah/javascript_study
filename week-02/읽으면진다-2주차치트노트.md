## 타입은 왜 있는가

컴퓨터의 메모리에는 0과 1만 들어갑니다. `01000001`이라는 여덟 자리가 저장되어 있을 때,
이게 숫자 `65`인지 문자 `A`인지 메모리만 봐서는 알 수 없습니다. **같은 비트를 무엇으로
읽을지 정해주는 약속**이 타입입니다.

그래서 타입은 값을 분류하는 이름표에 그치지 않고, **그 값으로 무엇을 할 수 있는지**를 정합니다.

```js
3 + 4        // 7      숫자끼리는 더합니다
'3' + '4'    // '34'   문자열끼리는 이어붙입니다
```

같은 `+` 기호인데 결과가 다릅니다. `+`가 두 가지 일을 하는 게 아니라, **자바스크립트가
양쪽 값의 타입을 보고 무엇을 할지 정하는 것**입니다. 타입을 모르면 결과를 예측할 수 없다는
말이 여기서 나옵니다.

여기서 자연스러운 질문이 생깁니다. **한쪽은 숫자고 한쪽은 문자열이면?** 그때 자바스크립트는
에러를 내지 않고 한쪽을 몰래 바꿔버립니다. 그 규칙이 이 언어에서 가장 악명 높은 부분이고,
다음 주에 한 번 마주치고, 10주차 즈음 형변환 주차에서 정면으로 다룹니다. 지금은 "타입이 다르면 무슨 일인가
일어난다" 정도만 알아두세요.

## 타입은 값에 붙어 있습니다

자바스크립트에서 **타입을 가지는 것은 값이지 변수가 아닙니다.**

```js
let something = 42;      // 지금 이 변수에는 숫자가 들어 있습니다
something = "마흔둘";     // 같은 변수에 문자열을 넣어도 문제없습니다
```

C나 Java 같은 언어는 변수를 만들 때 "여기엔 숫자만 넣겠다"고 미리 선언합니다.
자바스크립트는 그러지 않습니다. 변수는 그냥 **값을 가리키는 이름표**이고,
타입은 그 순간 가리키고 있는 값에 붙어 있습니다. 그래서 `typeof`는 변수가 아니라
**지금 그 변수에 들어 있는 값**의 타입을 알려줍니다.

이 성질이 편하기도 하고 위험하기도 합니다. 위험한 쪽은 이 과정 중반에 겪게 되고,
그 불편을 타입으로 막는 것이 마지막 여섯 주(TypeScript)의 주제입니다. 지금은
"타입은 값의 것"이라는 사실만 확실히 해두면 됩니다.

## 원시 타입

값의 종류는 크게 **원시 타입(primitive)** 과 **객체**로 나뉩니다. 원시 타입은 일곱 가지인데,
이번 주에는 다섯 가지만 다룹니다.

| 타입 | 예 | 설명 |
|---|---|---|
| `number` | `42`, `3.14`, `-1` | 숫자. **정수와 실수를 구분하지 않습니다** |
| `string` | `"안녕"`, `'a'`, `` `${x}원` `` | 문자열. 따옴표 세 종류 모두 가능 |
| `boolean` | `true`, `false` | 참/거짓. 비교 연산의 결과가 이것입니다 (다음 주) |
| `undefined` | `undefined` | 값이 아직 없음 |
| `null` | `null` | 값이 없음을 **일부러** 표시 |

나머지 둘(`symbol`, `bigint`)은 쓸 일이 생기는 주차에서 다룹니다.

숫자가 하나뿐이라는 건 다른 언어를 아는 사람에게는 낯선 부분입니다. `int`, `float`,
`double`이 따로 없고 전부 `number`입니다. 편하지만 대가가 있는데, 그 대가는 형변환을 다룰 때 봅니다.

객체(배열, 함수 포함)는 몇 주 뒤에 다룹니다. 원시 타입과는 **다루는 방식이 근본적으로 다릅니다.**
그 차이만 따로 다루는 주차가 따로 있습니다.

## `undefined`와 `null` — 없음이 왜 두 개인가

이번 주에서 가장 헷갈리는 지점입니다. 둘 다 "값이 없다"는 뜻인데 나뉘어 있습니다.
구분 기준은 **누가 넣었느냐**입니다.

```js
let 아직정하지않은값;
console.log(아직정하지않은값);   // undefined ← 내가 넣은 적이 없습니다

const 쿠폰없음 = null;          // null ← 내가 "없다"고 직접 적었습니다
```

- **`undefined`**: 자바스크립트가 넣습니다. 선언만 하고 값을 안 준 변수, 없는 속성을 읽었을 때,
  아무것도 `return`하지 않는 함수의 결과가 전부 `undefined`입니다. "아직/원래 값이 없다"는 상태입니다.
- **`null`**: 사람이 넣습니다. "여기에 값이 없다는 것이 정상이고, 그건 내 의도"라는 표시입니다.
  `shared/orders.json`의 `"coupon": null`이 그 예입니다. 쿠폰을 안 쓴 주문이라는 뜻이지,
  데이터가 빠진 게 아닙니다.

실무에서 이 구분이 무너지는 코드가 흔합니다. 지금 기준을 잡아두면 나중에 덜 헤맵니다.

## `let`과 `const`

차이는 하나입니다. **그 이름이 다른 값을 가리키도록 바꿀 수 있는가.**

```js
let 장바구니금액 = 10000;
장바구니금액 = 12000;        // 됩니다

const 무료배송기준 = 30000;
무료배송기준 = 50000;        // 에러
```

주의할 표현이 있습니다. `const`는 "값이 변하지 않는다"가 아니라 **"이 이름이 다른 값을
가리키지 못한다"**입니다. 지금은 두 말이 같아 보이지만, 객체를 배우고 나면
**전혀 다른 말이 됩니다.** 그때 이 문장을 다시 보게 됩니다.

무엇을 기본으로 쓸지는 정하기 나름입니다. 다만 기준이 있어야 하고, 그 기준을
`notes.md`에 적어두세요. 형변환 주차에서 그 답이 달라졌는지 확인합니다.

## `typeof`

값의 타입을 문자열로 돌려줍니다.

```js
typeof 42          // 'number'
typeof '안녕'       // 'string'
```

다만 `typeof`가 언제나 정직하지는 않습니다. 이번 과제에서 다섯 가지를 찍어보면
**하나는 예상과 다르게 나올 겁니다.** 그게 무엇인지, 왜 그런지는 지금 검색하지 말고
일단 결과만 기록해두세요. 이유는 10주차 즈음에 다룹니다.

## 타입 바꾸기 — 내가 직접 바꾸는 경우

타입을 확인했으면 바꿀 줄도 알아야 합니다. 필요한 상황은 생각보다 자주 옵니다.
화면의 입력창에서 읽어온 값은 `42`를 입력했어도 **문자열 `'42'`** 입니다. 그대로 더하면
계산이 아니라 이어붙이기가 됩니다.

바꾸는 함수는 타입 이름과 같습니다.

```js
Number('42')      // 42        문자열 → 숫자
String(42)        // '42'      숫자 → 문자열
Boolean(1)        // true      → 불리언
```

이렇게 **내가 코드에 적어서 바꾸는 것을 명시적 변환**이라고 합니다. 무엇이 무엇으로
바뀌는지 코드에 드러나 있어서 결과를 읽는 사람이 예측할 수 있습니다.

반대로 `'5' + 2`처럼 **내가 시키지 않았는데 언어가 알아서 바꾸는 것을 암묵적 변환**이라고
합니다. 코드 어디에도 "바꿔라"라고 적혀 있지 않아서, 규칙을 모르면 결과를 예측할 수 없습니다.
그 규칙 전체는 10주차 즈음에 다룹니다.

지금 잡아둘 원칙은 하나입니다. **타입을 바꿔야 한다면 직접 바꿔 적으세요.** 언어가 알아서
해주기를 기대하지 마세요.

변환이 실패할 수도 있습니다. `Number('안녕')`처럼 숫자로 볼 수 없는 값을 숫자로 바꾸면
`NaN`(Not a Number)이 나옵니다. 이번 주에는 그런 결과가 있다는 것만 확인하고 넘어가세요.
`NaN`은 성질이 특이해서 따로 다룰 값어치가 있고, 그건 형변환 주차 몫입니다.
