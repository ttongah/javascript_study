## `for`의 세 부분

```js
for (let i = 1; i <= 5; i++) {
  console.log(i);
}
```

괄호 안에 세 가지가 세미콜론으로 나뉘어 들어갑니다. 각각 실행되는 시점이 다릅니다.

| 자리 | 언제 실행되나 | 몇 번 |
|---|---|---|
| `let i = 1` (초기화) | 반복 시작 전에 딱 한 번 | 1번 |
| `i <= 5` (조건) | 매 회 블록 실행 **전** | 반복 횟수 + 1번 |
| `i++` (증감) | 매 회 블록 실행 **후** | 반복 횟수만큼 |

조건이 한 번 더 실행되는 게 이상해 보이지만 당연합니다. 마지막에 "이제 그만"이라고
판단하려면 조건을 한 번 더 검사해야 하니까요.

`i++`는 `i = i + 1`의 줄임입니다. W3에서 본 `+=`와 같은 부류입니다.

## 몇 번 도는가

여기서 한 번은 틀립니다. 하나 모자라거나 하나 넘칩니다.

```js
for (let i = 0; i < 5; i++)    // 0,1,2,3,4 → 5번
for (let i = 1; i <= 5; i++)   // 1,2,3,4,5 → 5번
for (let i = 1; i < 5; i++)    // 1,2,3,4   → 4번
for (let i = 0; i <= 5; i++)   // 0,1,2,3,4,5 → 6번
```

시작값과 조건은 짝으로 정해야 합니다. `0`에서 시작하면 `<`, `1`에서 시작하면 `<=`가
같은 횟수를 냅니다. 헷갈리면 **작은 수로 줄여서 직접 찍어보는 게** 제일 빠릅니다.
1부터 100까지가 헷갈리면 1부터 3까지로 바꿔 돌려보세요.

> **여기부터는 2단계 첫 항목의 답에 가깝습니다.** 누적 변수를 블록 안에 선언해서 한 번 돌려본 뒤에 읽으세요.

## 누적 변수는 바깥에

이번 주에서 제일 흔한 실수입니다.

```js
// 안 되는 코드
for (let i = 1; i <= 100; i++) {
  let 합계 = 0;      // 매 회 다시 0이 됩니다
  합계 += i;
}
```

블록 안에서 선언하면 **반복할 때마다 새로 만들어지고 0으로 초기화됩니다.**
쌓이질 않습니다. 게다가 블록 밖에서는 그 변수를 읽을 수도 없습니다.

```js
let 합계 = 0;                    // 반복문 바깥에서 한 번만
for (let i = 1; i <= 100; i++) {
  합계 += i;
}
console.log(합계);               // 5050
```

**초기값을 무엇으로 둘지**도 생각할 거리입니다. 더하기로 쌓으면 `0`, 곱하기로 쌓으면 `1`,
개수를 세면 `0`입니다. 최댓값을 찾을 때 `0`으로 두면 문제가 생기는데, 그건 다음 주에 다룹니다.

## `while`

`for`의 세 부분이 흩어져 있을 뿐 하는 일은 같습니다.

```js
let i = 1;              // 초기화 → 반복문 앞으로
while (i <= 5) {        // 조건 → 괄호 안에
  console.log(i);
  i++;                  // 증감 → 블록 안 끝으로
}
```

**둘 중 무엇을 쓸까.** 반복 횟수가 미리 정해져 있으면 `for`가 어울립니다.
세 부분이 한 줄에 모여 있어서 몇 번 도는지 한눈에 보입니다.
언제 끝날지 모르고 조건이 만족될 때까지 도는 경우에는 `while`이 자연스럽습니다.

절대 규칙은 아닙니다. 다만 자기 기준을 정해서 고르세요.

## 무한 루프

증감을 빠뜨리면 조건이 영원히 참입니다.

```js
let i = 1;
while (i <= 5) {
  console.log(i);
  // i++ 를 안 썼습니다
}
```

터미널이 끝없이 출력하며 멈추지 않습니다. **`Ctrl+C`로 멈춥니다.**
브라우저에서 만들면 탭이 얼어붙어서 탭을 닫아야 할 수도 있습니다.

원인은 대개 셋 중 하나입니다. 증감을 빠뜨렸거나, 증감 방향이 조건과 반대이거나
(`i--`인데 조건이 `i <= 5`), 조건에 쓴 변수를 블록 안에서 바꾸지 않은 경우입니다.

## `break`와 `continue`

- `break`: 반복문을 **완전히 빠져나갑니다.** 남은 회차는 실행되지 않습니다
- `continue`: 이번 회차만 건너뛰고 **다음 회차로 갑니다**

```js
for (let i = 1; i <= 10; i++) {
  if (i === 5) break;      // 1,2,3,4 출력하고 끝
  console.log(i);
}

for (let i = 1; i <= 10; i++) {
  if (i % 2 === 0) continue;   // 짝수만 건너뜀
  console.log(i);              // 1,3,5,7,9
}
```

`continue`로 걸러내는 것과 조건문으로 감싸는 것은 결과가 같습니다.

```js
if (i % 2 === 0) continue;
console.log(i);

// 같은 일
if (i % 2 !== 0) {
  console.log(i);
}
```

블록 안이 길어질수록 `continue` 쪽이 읽기 편해집니다. 들여쓰기가 한 단계 줄어드니까요.
짧을 때는 취향 문제입니다.

## 문자열 훑기

문자열도 `length`가 있고 인덱스로 글자를 꺼낼 수 있습니다.

```js
const 말 = '안녕하세요';
console.log(말.length);   // 5
console.log(말[0]);       // '안'
```

**인덱스는 `0`부터 시작합니다.** 그래서 마지막 글자는 `말[말.length - 1]`입니다.
`말[말.length]`는 없는 자리라 `undefined`가 나옵니다. 이 감각은 다음 주 배열에서
그대로 다시 쓰입니다.

글자를 세려면 누적 변수 하나와 반복문 하나면 됩니다.

```js
let 개수 = 0;
for (let i = 0; i < 말.length; i++) {
  if (말[i] === '하') {
    개수 += 1;
  }
}
```

없는 글자를 세면 `0`이 나옵니다. 에러가 아니라 그냥 `0`입니다.
"없음"과 "0개"가 같은 값으로 나오는 셈인데, 이 구분이 문제가 되는 상황은 나중에 만납니다.
