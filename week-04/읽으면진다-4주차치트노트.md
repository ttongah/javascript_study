## `if`는 무엇을 하는가

조건 자리에 들어온 값이 참이면 블록을 실행하고, 거짓이면 통째로 건너뜁니다.

```js
if (총액 >= 30000) {
  console.log('무료배송');
}
console.log('여기는 언제나 실행됩니다');
```

W3에서 확인했듯 `총액 >= 30000`은 그 자체로 이미 `true`나 `false`입니다.
`if`는 그 값을 **받아서** 쓰는 도구입니다. 값을 만드는 일과 흐름을 가르는 일은 별개입니다.

## `else if` 체인은 하나만 실행합니다

이게 이번 주에서 가장 중요합니다.

```js
if (조건A) {
  // A
} else if (조건B) {
  // B
} else {
  // 나머지
}
```

위에서부터 차례로 검사하다가 **처음 참이 되는 블록 하나만** 실행하고 나머지는 건너뜁니다.
조건 A와 B가 둘 다 참이어도 A만 실행됩니다.

반면 `else` 없이 `if`를 여러 개 나열하면 **참인 것이 전부 실행됩니다.**

```js
if (총액 >= 100000) { console.log('GOLD'); }
if (총액 >= 300000) { console.log('PLATINUM'); }
```

총액이 500,000이면 두 줄 다 출력됩니다. 구간을 나누는 문제에서는 거의 항상 버그입니다.

## 조건의 순서가 결과를 바꿉니다

`else if` 체인은 위에서부터 검사합니다. 그래서 **넓은 조건을 위에 두면 아래 조건에는 도달하지 못합니다.**

```js
// 잘못된 순서
if (총액 >= 100000) {
  등급 = 'GOLD';
} else if (총액 >= 300000) {
  등급 = 'PLATINUM';   // 여기에 절대 도달하지 못합니다
}
```

500,000원을 넣어보세요. 100,000 이상이니 첫 줄에서 걸려 `GOLD`가 됩니다.
`PLATINUM`이 나올 방법이 없습니다.

구간을 나눌 때는 **한쪽 끝에서부터 순서대로** 검사하면 안전합니다.
큰 값부터 내려오거나 작은 값부터 올라가는 식입니다. 순서가 섞이면 위와 같은 일이 생깁니다.

## 경계값과 `>=`

말로 된 기준을 조건으로 옮길 때 여기서 틀립니다.

| 말 | 조건 | 경계값 자신은 |
|---|---|---|
| 100,000원 **이상** | `총액 >= 100000` | 포함 |
| 100,000원 **초과** | `총액 > 100000` | 제외 |
| 100,000원 **미만** | `총액 < 100000` | 제외 |
| 100,000원 **이하** | `총액 <= 100000` | 포함 |

"100,000원 이상 ~ 300,000원 미만이 GOLD"라면, 100,000은 GOLD이고 300,000은 GOLD가 아닙니다.
개발자가 기준 숫자를 두고 이상인지 초과인지, 이하인지 미만인지 계속 묻는 것도 이 때문입니다.
헷갈리면 경계값을 직접 넣어 돌려보는 게 제일 빠릅니다. 이번 과제가 그걸 시키는 이유입니다.

**겹침과 빈틈**도 여기서 나옵니다.

- 두 조건의 기준이 둘 다 `>= 100000`처럼 같아지면 겹침
- `>= 100000`이어야 할 자리에 `> 100000`을 쓰면 정확히 100,000원인 사람이 어느 등급도 못 받습니다

## 조건 자리에 불리언이 아닌 값이 오면

```js
if (0) { }      // 실행 안 됨
if ('') { }     // 실행 안 됨
if (1) { }      // 실행됨
if ('가') { }   // 실행됨
```

`if`는 받은 값이 불리언이 아니면 참 쪽인지 거짓 쪽인지 알아서 판단합니다.
W3에서 `!0`이 `true`였던 것과 같은 이야기입니다. `0`과 빈 문자열이 거짓 쪽으로 취급됩니다.

이 성질은 편할 때도 있고 버그가 될 때도 있습니다. 특히 **`0`이 정상적인 값인 상황**에서
`if (수량)`이라고 쓰면 수량이 0일 때 "값이 없다"로 잘못 읽힙니다.
그 문제를 본격적으로 다루는 주차가 따로 있습니다.

## 기준값은 상수로

```js
// 이렇게 쓰면
if (총액 >= 100000) { }

// 6개월 뒤의 내가 이렇게 묻습니다: 100000이 뭐였지?
```

```js
const GOLD_기준 = 100000;
const PLATINUM_기준 = 300000;
const DIAMOND_기준 = 1000000;

if (총액 >= GOLD_기준) { }
```

이름이 붙으면 조건문이 규칙 문장처럼 읽힙니다. 그리고 기준이 바뀔 때 **한 군데만** 고치면 됩니다.
같은 숫자가 조건문과 출력 문구에 흩어져 있으면 한 군데를 빠뜨려서 화면과 판정이
어긋난 채로 조용히 돌아갑니다. W3 윤년 과제에서 본 것과 같은 종류의 버그입니다.

> 위 코드는 읽기 편하도록 한글 이름을 썼습니다. 실제로는 변수 이름을 영문 대문자 스네이크 케이스로 쓰는 것이 관례입니다.

## `else`가 필요한 자리, 아닌 자리

`else`는 "나머지 전부"를 뜻합니다. 남는 경우를 반드시 처리해야 하면 필요하고,
아니면 없어도 됩니다.

등급 판정처럼 **모든 금액이 어느 하나에 속해야 하는** 경우에는 마지막을 `else`로 닫는 편이
안전합니다. 그러면 빈틈이 생길 수 없습니다. 반대로 마지막도 `else if`로 두면
조건을 잘못 써서 아무 데도 안 걸리는 금액이 생겨도 아무 일도 안 일어나서 눈치채기 어렵습니다.

다만 조건에 빈틈이 생기면 그 빈틈에 걸린 값이 `else` 블록의 결과를 받는다는 점은 기억해두세요.
`else`에서 오류를 발생시키는 것도 방법입니다. 이건 나중에 다룹니다.
