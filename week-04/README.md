# W4 — 조건문

**주제**: `if` / `else if` / `else`, 조건의 순서, 경계값, 기준값 상수화

## 학습목표

W3에서 비교와 논리 연산이 `true`나 `false`를 만든다는 걸 봤습니다. 이번 주는 그 값에 따라
**실행할 코드를 고릅니다.**

문법 자체는 반나절이면 익힙니다. 실제로 틀리는 자리는 따로 있습니다. **경계값**과
**조건의 순서**입니다. 99,999원과 100,000원 사이에서 등급이 하나 어긋나는 버그는
문법을 몰라서 생기는 게 아닙니다. 이번 과제는 그 둘만 다룹니다.

- `if` / `else if` / `else`로 값에 따라 다른 코드를 실행할 수 있다.
- 비교와 논리 연산의 결과를 조건 자리에 넣어 쓸 수 있다.
- 조건 자리에 불리언이 아닌 값을 넣으면 어떻게 되는지 확인하고 설명할 수 있다.
- "이상"과 "초과"를 구분해, 경계값이 어느 쪽에 들어가는지 정확히 조건으로 옮길 수 있다.
- 조건을 검사하는 순서가 결과를 바꾼다는 것을 재현해 보이고, 왜 그런지 설명할 수 있다.
- 조건 구간에 겹침이나 빈틈이 없는지 스스로 점검할 수 있다.
- 조건문에 쓰이는 기준값을 상수로 뽑아 이름으로 의도를 드러낼 수 있다.
- `else`가 필요한 자리와 필요 없는 자리를 구분할 수 있다.

> 한 가지 주제가 90분 넘게 막히면 질문하세요. 30분쯤 막히면 `week-04/읽으면진다-4주차치트노트.md`를 보셔도 됩니다.
> 단, **1단계를 직접 해본 뒤에** 펴세요.

---

## 과제: 조건문 익히고, 등급 판정기 만들고, 깨뜨려보기

### 1단계 — 조건문 익히기

`week-04/playground.js`를 만들어 아래를 직접 돌려봅니다.
관찰한 것은 `week-04/notes.md`에 적습니다.

- [ ] `if` 하나만 써보기
  - 블록 안에 `console.log('블록 안')`, 블록 뒤에 `console.log('블록 뒤')`를 두기
  - 조건을 `true`로 한 번, `false`로 한 번 실행
  - **`notes.md`에 적을 것**: 조건이 거짓일 때 출력된 줄과 출력되지 않은 줄
- [ ] `if` / `else`로 두 갈래 만들기
  - 두 블록에 서로 다른 문장을 출력하게 하고, 조건을 바꿔가며 두 경우를 모두 실행
  - **`notes.md`에 적을 것**: 두 블록이 동시에 실행되는 경우가 있었는지 (예/아니오와 근거)
- [ ] `else if`를 넣어 세 갈래로 만들기
  - 조건을 `점수 >= 60`, `점수 >= 80`, `else` 순서로 두고 각 블록에 다른 문장 출력
  - **`점수 = 90`을 넣어 실행하세요.** `90`은 위 두 조건을 모두 만족합니다
  - **`notes.md`에 적을 것**: 출력된 문장이 몇 개였는지, 그리고 셋 중 어느 블록이 실행됐는지
- [ ] 같은 세 갈래를 `else` 없이 `if` 세 개로 다시 쓰기
  - 조건은 그대로 두고 `else if`를 전부 `if`로 바꾸기
  - 다시 `점수 = 90`으로 실행
  - **`notes.md`에 적을 것**: 이번에는 출력된 문장이 몇 개였는지, 앞의 결과와 무엇이 달랐는지
- [ ] 조건 자리에 불리언이 아닌 값 넣어보기
  - `if (0)`, `if ('')`, `if (1)`, `if ('가')` 네 개를 각각 실행하고 블록이 실행되는지 확인
  - W3에서 `!0`이 `true`였던 것과 이어지는 이야기입니다
  - **`notes.md`에 적을 것**: 네 값 중 블록이 실행된 것과 실행되지 않은 것을 나눠 적기

### 2단계 — 등급 판정기 만들기

`week-04/grade.js`를 만듭니다.

- [ ] 누적 구매액을 변수에 담고, 조건문으로 등급을 판정해 출력하기

  | 누적 구매액 | 등급 |
  |---|---|
  | 100,000원 미만 | `SILVER` |
  | 100,000 이상 ~ 300,000 미만 | `GOLD` |
  | 300,000 이상 ~ 1,000,000 미만 | `PLATINUM` |
  | 1,000,000 이상 | `DIAMOND` |

  - 출력 형태는 `320000원 → PLATINUM`처럼 금액과 등급이 함께 보이게 할 것
- [ ] 기준 금액 세 개(`100000`, `300000`, `1000000`)를 각각 상수로 선언해서 조건문에 쓰기
  - 조건문 안에 숫자가 남아 있으면 안 됩니다
- [ ] 아래 여섯 금액을 하나씩 넣어 실행하고, 나온 등급을 `notes.md`에 표로 옮기기

  | 금액 | 기대 등급 |
  |---|---|
  | 99,999 | SILVER |
  | 100,000 | GOLD |
  | 299,999 | GOLD |
  | 300,000 | PLATINUM |
  | 999,999 | PLATINUM |
  | 1,000,000 | DIAMOND |

  - 하나라도 기대와 다르면 그 경계에서 `>`를 써야 할 자리에 `>=`를 썼는지(또는 반대인지) 확인해 고치기
  - **`notes.md`에 적을 것**: 처음에 틀린 금액이 있었다면 무엇을 어떻게 고쳤는지
- [ ] `GOLD` 기준 상수만 `100000`에서 `50000`으로 바꿔 다시 실행하기
  - 60,000원을 넣었을 때 등급이 바뀌는지 확인
  - **`notes.md`에 적을 것**: 코드에서 몇 군데를 고쳐야 했는지
  - 확인 후 상수를 원래대로 되돌릴 것

### 3단계 — 일부러 깨뜨려보기

각 실험은 **확인한 뒤 반드시 원래대로 되돌립니다.** 최종 제출 코드는 정상 동작해야 합니다.

- [ ] 조건 순서 뒤집기
  - `else if` 체인의 순서를 `DIAMOND` 판정이 맨 아래로 가도록 바꾸기
    (즉 `>= 100000`을 맨 위, `>= 1000000`을 맨 아래로)
  - 이 상태에서 **2,000,000원**을 넣어 실행
  - **`notes.md`에 적을 것**: 나온 등급, 기대했던 등급, 그리고 왜 그렇게 나왔는지 한 문단
    (`else if` 체인이 위에서부터 검사한다는 것이 답의 절반입니다)
- [ ] 구간에 빈틈 내기
  - `GOLD` 조건의 `>=`를 `>`로 바꾸기
  - 이 상태에서 **정확히 100,000원**을 넣어 실행
  - **`notes.md`에 적을 것**: 이 금액이 어느 등급을 받았는지, 그리고 왜 그렇게 됐는지
- [ ] 구간 겹치게 하기
  - `PLATINUM` 조건의 기준을 `GOLD`와 같은 값(`100000`)으로 바꾸기
  - **500,000원**을 넣어 실행
  - **`notes.md`에 적을 것**: 나온 등급과, 두 조건이 겹칠 때 무엇이 이기는지

### 제약

- **함수를 쓰지 마세요.** 변수와 조건문만으로 해결할 것
  - 함수는 몇 주 뒤에 다룹니다. 이번 주 코드를 그때 함수로 옮기게 됩니다
- 조건문에 숫자를 직접 쓰지 말고 상수로 뽑을 것
  - `if (total >= 100000)`만 보면 그 숫자가 무엇인지 알 수 없습니다. 기준이 바뀔 때 고칠 자리도 흩어집니다
- `else if` 체인 하나로 해결할 것. 조건 안에 조건을 넣지 말 것
  - 구간을 나누는 문제라 중첩이 필요 없습니다. 중첩이 생겼다면 구간을 잘못 나눈 겁니다
- "이상"과 "초과"를 구분해서 쓸 것. `>`와 `>=`를 아무렇게나 바꾸지 말 것
  - 이번 주 버그는 대부분 여기서 나옵니다
- `switch` 사용 금지
  - 값이 딱 떨어지는 경우에 쓰는 도구입니다. 구간을 나누는 이번 문제에는 맞지 않습니다
- `var` 금지, 의미 없는 변수 이름 금지 (W2·W3과 같은 규칙)

### 완료 기준

`notes.md`만 읽고도 아래에 답할 수 있으면 통과입니다.

- `grade.js`가 에러 없이 실행되고, 경계값 여섯 개가 전부 기대 등급으로 나옴
- 여섯 금액의 실행 결과가 표로 기록되어 있음
- **`점수 = 90`일 때 `else if` 체인은 몇 개를 출력했고, `if` 세 개짜리는 몇 개를 출력했는지**가 각각 적혀 있음
- `if (0)` · `if ('')` · `if (1)` · `if ('가')` 중 블록이 실행된 것과 안 된 것이 나뉘어 적혀 있음
- **순서를 뒤집고 2,000,000원을 넣었을 때** 나온 등급과 그 이유가 적혀 있음
- **`>=`를 `>`로 바꾸고 100,000원을 넣었을 때** 어떻게 됐는지 적혀 있음
- **두 조건을 겹치게 하고 500,000원을 넣었을 때** 어느 쪽이 이겼는지 적혀 있음
- 조건문 안에 숫자 리터럴이 하나도 없고, 상수를 바꾸면 판정이 따라 바뀜
- `else`를 마지막에 쓴 이유(또는 쓰지 않은 이유)가 한 문장으로 적혀 있음
